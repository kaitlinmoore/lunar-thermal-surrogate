# Changelog

Instrument and design changes, one line each: date | instrument | change | reason. Notes whether held-out data was involved.

- 2026-11-23 | environment | Python 3.12; core `nvidia-physicsnemo` 2.3.0 with PyTorch from PyTorch's cu130 index (no cu12/cu13 extra); uv environment per checkout in the WSL filesystem via `.envrc` | RTX 5080 (sm_120) needs a CUDA 12.8+ build of PyTorch; the cu13 extra would pull RAPIDS, CuPy and DALI and pins `numpy<2.5`, which conflicts with the vendored illumination code's `numpy>=2.5.4`. No held-out data involved.
- 2026-11-23 | regolith parameters | defaults from Hayne et al. (2017) Table A1, including H = 0.06 m (Table A1 average; the main text gives 0.068 m, open) | standard model of the published Diviner fit; numbering from arXiv:1711.00977. No held-out data involved.
- 2026-11-23 | solver grid | first layer = surface skin depth / 20 (m = 20), each layer 1.1 times the one above (n = 10), bottom at 10 skin depths of the deep material, skin depths evaluated at 250 K (39 nodes, 2.0 mm top layer, 0.73 m column for one lunation) | convergence study on synthetic equatorial forcing: the paper's m = 10, n = 5 leaves 0.7 K maximum surface error at sunrise; m = 20, n = 10 leaves 0.19 K for twice the cost; bottom depth converged by 6 skin depths. No held-out data involved.
- 2026-11-23 | solver time step | BDF2 with Newton iteration, internal step at most 1800 s (forcing intervals split into equal substeps) | adds at most 0.015 K over a 30 s step at hourly forcing; implicit, so stable at any step. No held-out data involved.
- 2026-11-23 | spin-up tolerance | 0.01 K on both the largest cycle-to-cycle change (all nodes, all sample times) and the projected remaining drift; extrapolation along the slow mode when its decay ratio is stable and at most 0.98 | a per-cycle criterion alone stopped 0.2-0.4 K short of steady state at depth (decay ratio 0.95 per lunation); converged runs land within 0.009 K of a 1e-6 K reference. No held-out data involved.
- 2026-11-23 | illumination engine | vendored Penumbra Luna's `lss` engine unchanged into `src/lss/` from nasa-lunar-site-scout commit `aef153a` (Apache-2.0 kept; SHA-256 manifest in `src/lss/VENDORED.md`), with its fetch script and engine tests; copied its `data/` and `kernels/` into `LSS_DATA_DIR`; added `scripts/illumination_point.py` | forcing source for the training data, copied rather than imported so the repo runs on its own. No held-out data involved: the two demonstration points are 95 km and 1134 km from the nearest of the 23 sites (the copied engine tests do read site terrain, as in Penumbra Luna).
- 2026-11-23 | triangulation reference | added `heat1d` (github.com/phayne/heat1d, MIT) as a dev dependency pinned to commit `5b73a6c` (Python package 0.4.1, unreleased; `python/` subdirectory), with `scripts/triangulate_heat1d.py`, `tests/test_triangulation.py` and a registered pytest `slow` marker | independent implementation of Hayne et al. (2017) to triangulate the solver against; the solver itself is unchanged. No held-out data involved: all cases are flat surfaces at a latitude.
- 2026-11-23 | continuous integration | GitHub Actions workflow runs ruff check, ruff format --check and `pytest -m "not gpu and not data"` on push and pull request to main, with the locked CUDA 13 PyTorch on a CPU runner and the uv cache keyed on `uv.lock` | catches a broken change on its pull request before merge; GPU and data tests stay local because the runner has neither. No held-out data involved.
- 2026-11-23 | lint configuration | `[tool.ruff]` in pyproject.toml: default rules and line length (88), excluding only code copied from Penumbra Luna (`src/lss`, `tests/lss/engine`, `tests/lss/contract`, `scripts/fetch_data.py`); format-only changes to `scripts/illumination_point.py`, `tests/test_vendored.py` and `tests/lss/conftest.py` | the repo had no ruff config, and CI's lint and format checks failed on vendored code that is never edited here and follows its own project's settings. No held-out data involved.
- 2026-11-23 | vendored engine tests | `test_series.py::test_fraction_limits_and_half[True]` marked as a non-strict expected failure in `tests/lss/conftest.py` (the copied test is unchanged) | it asserts an exact 0.0 and a GitHub hosted runner returned 4.4e-19 on one run and passed on the next; it still runs and reports XPASS when it passes. Upstream fix (a tolerance) belongs in Penumbra Luna. No held-out data involved.
- 2026-11-23 | illumination engine | re-copied `src/lss` from nasa-lunar-site-scout `9d0c648` (was `aef153a`): `registry/terrain.py`, `horizon/core.py` and `horizon/cache.py` changed upstream, every other file is identical; re-copied `test_series.py`, `test_terrain.py` and `test_global_layer.py`; removed the non-strict expected failure on `test_fraction_limits_and_half[True]` from `tests/lss/conftest.py` | upstream fixes: where 400 km rays leave the 240 m south polar map (about 73°S to 60°S, and the map's corners north of 60°S) the resolver now adds `LDEM_128` as far field beyond the map's full reach, so those horizons have 0 missing samples (were 1.5% at 70°S, 7.1% at 65°S, 15.9% at 61°S and up to 24% in the corners, with the gaps towards the Sun); the exact-zero test now uses a tolerance. Checked: both demonstration outputs array-equal to the earlier run; resolver stacks at 1,000 random points (250 each south of 80°S, 74–80°S, 60°S–60°N, north of 74°N) unchanged except 7 in the 240 m map's corners north of 60°S, which get the same fix. No held-out data involved: resolver stacks only at the random points, and the 11 points whose horizons were computed are 340 km or more from the nearest of the 23 sites; sites are read only by the copied engine tests.
